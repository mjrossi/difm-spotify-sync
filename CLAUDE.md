# difm-spotify-sync — project conventions

This file is the contract for how code in this repo is written. Read it
before making non-trivial changes.

Conventions here follow the maintainer's `urbanist-atlas` project; where
this repo is silent, that one is the reference.

## What this is

A Go service that mirrors DI.fm liked tracks into a Spotify playlist.
Single module. Runs as one container on a homelab host, on an internal
network — nothing about it is public-facing.

## Tooling: mise

Runtimes and project tools are managed by [mise](https://mise.jdx.dev).
`mise install` at the repo root provisions everything pinned in
`mise.toml`: Go, sqlc, goose, just, golangci-lint.

- **`mise.toml`** — base: tool versions + production-default env.
- **`mise.development.toml`** — local overrides; `MISE_ENV=development`.
- **`mise.ci.toml`** — CI overrides; `MISE_ENV=ci`.
- **`mise.local.toml`** — gitignored, machine-specific and credential-bearing.
  See `mise.local.toml.example`.

Add tooling by editing `mise.toml` rather than telling contributors to
`brew install` things.

## Go conventions

- **Standard library first.** Pull a dependency only when stdlib genuinely
  can't do it, and **ask the maintainer before adding one**. Current set:
  - `github.com/urfave/cli/v3` — CLI / config
  - `golang.org/x/oauth2` — OAuth2 token refresh
  - `modernc.org/sqlite` — pure-Go SQLite driver (no CGO)
  - `github.com/pressly/goose/v3` — migrations
  - `github.com/google/go-cmp/cmp` — diff-friendly test assertions
- **Logging:** `log/slog` (stdlib). JSON in prod, text in dev.
- **Errors:** stdlib `errors` + `fmt.Errorf("...: %w", err)`. No third-party
  errors libraries. Sentinel errors where callers must branch
  (`difm.ErrUnauthorized`).
- **Config:** urfave/cli flags with `DIFMSYNC_*` env-var fallbacks. No viper.
- **Layout:** `cmd/` binaries, `pkg/` importable library, `internal/`
  non-exported.
- **SQL:** hand-written queries in `internal/store/sqlite/queries/`,
  bindings generated by sqlc (`just gen`). Never hand-edit
  `internal/store/sqlite/gen/`. Schema changes are goose migrations in
  `migrations-sqlite/`, embedded via `//go:embed`.
- **Style:** golangci-lint v2 (`.golangci.yml`) is the single lint + format
  gate. `just lint` checks, `just fmt` applies. Note `misspell` is set to
  US English.
- **Module path:** `github.com/mjrossi/difm-spotify-sync`.

The design is **library-first**: `pkg/difm` and `pkg/match` are useful
independently of this binary and must not import `internal/`.

## The Spotify API

The client in `pkg/spotify` is hand-rolled on `net/http`. This is
deliberate: `zmb3/spotify` (the established Go wrapper) last shipped
2024-11-11 and hardcodes `POST /playlists/{id}/tracks`, which Spotify's
**February 2026 API migration deprecated**. That path now returns a bare
`403 Forbidden` with an empty body for Development Mode apps, so the
library cannot perform this project's central write at all.

Migration facts worth remembering, since the 403 gives no clue:
- `POST /playlists/{id}/tracks` → **`POST /playlists/{id}/items`**
- `DELETE` body key `tracks` → **`items`**
- Read responses: `items[].track` → **`items[].item`**

`TestAddToPlaylistUsesItemsEndpoint` pins the path so a regression fails
in CI rather than in production.

Two further rules the client enforces, because the engine depends on
being able to branch on them:

- **429 and 401/403 are typed** (`spotify.ErrRateLimited`, carrying
  `Retry-After`, and `spotify.ErrUnauthorized`). A rate limit read as an
  empty search result becomes a permanent wrong verdict for every track
  it touched. `pkg/difm` mirrors both.
- **ISRC is checked first.** DI.fm supplies one for many tracks and it
  identifies the exact recording, so it settles the match outright
  instead of going through fuzzy scoring — which is where the wrong edit
  gets picked.

## The DI.fm API

Private, undocumented, unversioned, and restricted before. Treat
[`docs/difm-api.md`](docs/difm-api.md) as the only record of it, and keep
it current when behaviour changes.

Consequences for code:
- Decode defensively. Unknown fields ignored, absent fields zero, a
  malformed record skipped rather than failing the batch.

  Skipping it is only half the rule, and the two halves are easy to
  mistake for a contradiction with invariant 2 below. A skipped record is
  a like that reached no durable state anywhere, so the client returns
  `difm.ErrDropped` alongside the records it *did* read: the batch
  survives, and the pass is still marked unclean so the watermark holds.
  The cost is that a persistently unreadable record stalls the watermark
  and is re-read every pass. That is deliberate — a loud stall in
  `sync_runs.error` is recoverable and a silent skip is not.

  Termination during pagination keys on the **raw record count**, never
  on how many usable tracks a page produced. A page whose records are all
  downvotes or all malformed yields nothing and is not the end of the
  list; conflating the two truncated the history and reported success.
- `per_page` is ignored by the server; paginate by short page only, and
  terminate on the raw record count rather than the usable-track count.
- Votes arrive newest-first. The pagination short-circuit depends on it;
  see the Ordering section of `docs/difm-api.md` for why a change there
  fails silently.
- Never automate against `www.di.fm` — it is Cloudflare-fronted and will
  403. `api.audioaddict.com` is the only supported host.

## Sync semantics

One-way, add-only. Spotify deletions are not reverted; DI.fm un-likes are
not propagated. Full mirroring is explicitly out of scope for v0.1.

Three invariants that the code depends on, in order:

1. **Spotify write, then ledger, then watermark.** A crash between any two
   must cause a redundant re-read, never a silent skip. Never reorder these.
   The ledger write and the watermark share one transaction, so the
   watermark can never land ahead of the ledger.
2. **The watermark advances only after a fully clean pass.** A partial
   failure must leave it where it was.

   "Partial failure" means *any* error the pass swallowed to keep going —
   not only one that aborted it. A failed search, a failed review-queue
   write, and a record `pkg/difm` could not decode all count. The engine
   tracks this explicitly (`passClean`) rather than inferring it from
   control flow, because the failure mode is silent: the watermark filters
   at fetch time, so advancing past a like that was never durably recorded
   means nothing ever re-reads it, and `resync` cannot recover it either.

   A pass that swallowed anything returns `syncer.ErrPassIncomplete`, so a
   one-shot `difmsync sync` exits non-zero. `Loop` logs it and carries on —
   the watermark held, so the next tick re-reads whatever was missed.

   Correspondingly, a transport failure is never recorded as a *verdict*.
   "We could not ask Spotify" must not be stored as `no_match`.
3. **Dedupe is reconciled, not assumed.** Each pass reads live playlist
   contents in addition to the ledger, so the two disagreeing (restored DB,
   `resync --forget-all`, manual add) cannot duplicate.

`resync` is the recovery escape hatch and must clear *both* suppressors —
ledger row and watermark. Clearing only the ledger is a silent no-op,
because the watermark filters at fetch time.

`--forget=<id>` therefore rewinds the watermark to just before that like,
rather than leaving it alone or clearing it outright: leaving it makes the
command do nothing, and clearing it resets all of history, which is a much
larger instruction than the operator gave.

## Testing

- `pkg/match` is where matching quality is proven. Any weight or
  threshold change must keep both directions passing: wrong edits stay
  below the auto bar, and genuine matches stay above it.
- The DI.fm client tests run against a recorded fixture
  (`pkg/difm/testdata/`), never the live API.
- `just check` (lint + race tests + codegen drift) is the gate before pushing.

## Deployment

One container on the homelab, built on the host from this repo; see
[`docs/deploy.md`](docs/deploy.md) for the runbook. Two constraints that
are easy to get wrong:

- The sync interval is an **internal ticker**, not cron. Nothing external
  triggers a pass, so a container that is stopped, unhealthy, or
  crash-looping simply stops syncing — silently, unless something is
  watching. That is what `difmsync status --check` and `/healthz` are
  for; see the Operator surface section below.
- `difmsync auth` is the one step that cannot run headless. It must write
  to the same database the deployment mounts. Its listener binds the
  redirect URL's host and path; in a container the host must be
  overridden to `0.0.0.0` (`DIFMSYNC_AUTH_BIND`), because a published
  port forwards to eth0 rather than loopback.

## Credentials

`DIFMSYNC_API_KEY` is a long-lived DI.fm token with no visible rotation
path, and it is inlined in DI.fm's authenticated page HTML — so treat it
as a shared-fate secret. It never goes in the repo, in logs, or in
`docs/`. No DI.fm password is needed at any point.
